# P4 --- Tasks atômicas

Refinar cada item em uma task individual segundo `docs/TASK_SPEC.md`
antes de enviar ao Executor. Executar uma task atômica por vez, sem
antecipar as seguintes.

Gate conceitual: `CODEX_TASK → Executor → CODEX_RESULT`.

## Fronteira P4/P5

> P4 sabe executar uma CODEX_TASK e produzir um CODEX_RESULT.
> P5 decide quando executar e como aplicar o resultado ao workflow/TaskState.

Não pertence ao P4; pertence ao P5 ou tópicos posteriores:

- Planner disparando automaticamente Executor;
- atualização de TaskStatus baseada no resultado;
- workflow end-to-end Planner → Executor;
- retries coordenados pelo Orchestrator;
- Discord disparando execução completa;
- scheduling/queue;
- execução paralela;
- múltiplos providers dinâmicos;
- PR/merge automático;
- recovery global do Orchestrator.

## P4.1 --- Official Codex Integration Discovery + ADR

- **Objetivo:** verificar opções oficiais atuais da OpenAI/Codex e registrar
  a decisão arquitetural em ADR antes de qualquer integração concreta.
- **Discovery obrigatório:** investigar posteriormente, durante P4.1:
  APIs oficiais; SDKs oficiais; protocolos disponíveis; Codex SDK;
  app-server; CLI/exec quando aplicável; exec-server/self-hosted quando
  aplicável; Responses API quando aplicável; autenticação; working directory;
  sandbox; approvals; structured output; streaming/eventos;
  timeout/cancelamento; persistência/retomada de sessão; compatibilidade
  com Go e Linux/Docker.
- **Aceite:** opções oficiais atuais verificadas e decisão registrada no ADR.
- **NÃO FAZER:** implementar adapter por suposição ou assumir antecipadamente
  API, SDK, CLI, app-server, exec-server, autenticação, sessão ou protocolo.

Amendment P4.1b: a ADR revisa o caminho principal para **Sign in with ChatGPT

## P4.2 --- Executor Contracts + ExecutorPort

- **Depende:** P4.1.
- **Objetivo:** criar contratos provider-independent do Executor e ExecutorPort.
- **Aceite:** domínio/application sem dependência de tipos OpenAI/Codex;
  decisão concreta de estados/contratos respeita o ADR do P4.1.

## P4.3 --- Execution Package + Policy

- **Depende:** P4.2 e ExecutorTaskSpec produzido pelo P3.
- **Objetivo:** transformar o `ExecutorTaskSpec` em um pacote de execução
  seguro e estabelecer limites/policy de execução.
- **Aceite:** preservar Objective, Scope, Constraints e AcceptanceCriteria.
- **NÃO PERMITIR:** shell arbitrário, executable arbitrário, argv livre vindo
  do modelo, expansão silenciosa de scope ou provider enfraquecendo policy.

## P4.4 --- Codex Provider Adapter

- **Depende:** P4.1–P4.3; resultados dos spikes e decisão registrados na ADR.
- **Implementação:** LIBERADA (`implementation=ALLOWED`).
- **Live validation:** BLOCKED by `B-P4-001`.
- **Objetivo:** implementar `ExecutorPort` usando SOMENTE o mecanismo oficial
  escolhido na ADR de P4.1, revisada por P4.1b (ChatGPT OAuth + app-server).
- **Aceite:** conceitos específicos OpenAI/Codex ficam no adapter;
  domain/application permanecem provider-independent.
- **Execução:** TDD com testes independentes da integração live. Direção
  arquitetural (não declaração de tipos já existentes): `ExecutorPort →
  CodexProviderAdapter → CodexRuntimePort → DockerCodexRuntime → codex app-server`.
  Docker, app-server, OAuth, account routing, provider IDs e eventos Codex
  permanecem fora dos contratos de domínio/application.
- **Falha live:** `workspace routing discovery failed` deve resultar em
  fail closed, normalização de falha provider/runtime e retorno controlado;
  nunca sucesso, ampliação de permissões, troca de autenticação ou fallback
  automático para API key. Detalhes de `CODEX_RESULT` pertencem ao P4.5.

## P4.5 --- Result Normalization + CODEX_RESULT

- **Depende:** P4.4.
- **Objetivo:** converter resultado específico do provider em contrato tipado
  do Executor e produzir `CODEX_RESULT`.
- **Aceite:** preservar evidências relevantes de outcome, resumo, arquivos
  alterados, testes, validações e bloqueios/falhas.
- **NÃO FAZER:** contratos principais baseados em `map[string]any`.

## P4.6 --- ExecutorSession, Limits + Integrated Validation

- **Depende:** P4.5.
- **Objetivo:** fechar o Executor com ExecutorSession, timeout, cancellation,
  output limits, provider failures, malformed results, cleanup e testes
  integrados P4.
- **Aceite:** `ExecutorSession != TaskState`; cada execução deve poder ser
  tratada como sessão descartável.
- **Enquanto B-P4-001 estiver aberto:** testes integrados podem usar fake
  runtime, deterministic test double ou controlled local runtime. Isso não
  comprova live integration; a validação live permanece separadamente BLOCKED
  por `B-P4-001`.
- **Validação final prevista, quando aplicável:**

  ```text
  ./scripts/validate.sh
  go test -race ./internal/...
  git diff --check
  ```

  Para tasks Go, o aceite final usa Linux via Docker, incluindo
  `./scripts/validate.sh` dentro do container Linux.
